# SNF ledger epoching — design draft (Item 4a)

Status: draft, staged behind the 0x09 refinement bid. Registry persistence
(the security-relevant half of Item 4a) is already implemented: settled
states snapshot to `<state>.registry` on every bounty and overlay after
corpus re-registration at boot.

## Problem

`Treasury.entries` is an append-only journal: every enroll, settle, recall
fee, door fee, tithe, solve, and refine appends a row. Under registered-work
throughput (1,120 tasks dispatching continuously, plus the market's settle
traffic) the journal grows without bound — the same growth class the demand
market had before thermodynamic capacity. Restart replay time and resident
memory both scale with journal length rather than with economic state.

## Invariants to preserve

Conservation: `pool + Σ balances = Σ stakes` at every prefix of the journal.
Any compaction preserves (a) this equation, (b) per-identity balances
exactly, and (c) the K-step receipt chain's continuity (the chronometric
spine is content-addressed; folding must not orphan receipts the court can
still be asked to replay).

## The fold (Smith normal form)

The journal is a 1-chain of transfers over the identity lattice: each entry
is a signed edge `who --μ⃗--> who'` (the pool is an identity). Compaction is
a boundary fold: present the epoch's entries as the integer matrix `D` of
the transfer complex and reduce `D → SNF = diag(d₁…dₖ)`; the epoch's net
effect on every identity is the image — a single balance 0-chain `B₀`.
Everything in the kernel (closed circulation loops: A→B→A, tithe
round-trips, door-fee refunds) vanishes exactly. Closed chains carry no
economic information forward; removing them is the compression.

An epoch closes when the journal's length crosses the same thermodynamic
capacity reading the market uses (derived from available memory — no static
row limit). On close:

1. Freeze the epoch prefix; compute `B₀` (per-identity net) and verify
   conservation against the live pool.
2. Write one `epoch` row per identity with nonzero net (kind `"epoch"`,
   orientation 0 — a fold is neither work nor spend), anchored to the last
   K-step receipt of the folded prefix so the chronometric chain stays
   connected.
3. Archive the folded prefix to `<state>.epoch-N` (cold, append-only,
   auditable; never deleted — the court can replay any epoch by loading its
   archive).
4. Truncate the live journal to `[epoch rows] + [post-freeze tail]`.

## Restore path

Boot restore reads epoch rows exactly like any other entry — no special
case: the fold is ordinary journal content. A server that never epochs and
one that epochs hourly converge to identical balances; only the resident
footprint differs.

## Interaction with provisional escrow

Escrowed (provisional) awards do not fold: they are open 1-cells awaiting a
court verdict, and folding them would erase the escrow the verdict releases
or slashes. The freeze line therefore slides back to exclude the oldest
open provisional — an epoch closes only behind a fully-final prefix.

## Out of scope here

- Registry archive (settled snapshots are already small: 37 B/task).
- Cross-server ledger reconciliation (each server folds its own journal;
  escrow-gossip already carries the inter-instance stakes).
