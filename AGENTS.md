## Before writing

1. Read the specification of the area whole, and the sections the code
   comments cite.
2. Name the structure the change uses for each row of the table above
   that it touches.
3. Write the claims first, as statements of the algebra (MU-STANDARDS
   3.1), including a `compile_fail` doc test where a guard type makes a
   wrong structure unwritable.

## While writing

- Never run `cargo fmt`. The tree is not `rustfmt`-clean by design.
- Use no possessive or personal pronouns in code, comments, test names,
  identifiers or documents: name the thing.
- Keep a source file within the reading bound, with one organ per file.
- Keep public documents general. Integration specifics of a particular
  peer kernel belong in that kernel's own repository.

## Before a pull request
